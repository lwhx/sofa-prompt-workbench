# 沙发场景提示词反推

## 任务目标

读取两张图片并输出文字，不生成图片，不调用即梦，不连接图床、表格或其他外部服务。

固定输入顺序：

1. 图1：客厅场景参考图。
2. 图2：沙发白底产品图。

最终提示词必须把场景内容全部转写成文字，使用户后续只上传沙发白底产品图即可使用。

## 输入检查

- 同时收到两张可辨识图片时直接分析，不重复确认。
- 只收到一张、图片无法读取、顺序不明确或无法判断哪张是白底产品图时，只询问缺失或模糊的信息，不猜测。
- 用户补充人物、尺寸、风格、茶几或动线要求时，将其作为高优先级约束。

## 执行流程

### 1. 解析图1场景

识别并记录：

- 装修风格、色调、住宅尺度和真实居住氛围。
- 客厅、餐厅、厨房、水吧、过道和入口之间的关系。
- 主通道位置、家具间距以及可能被沙发遮挡的动线。
- 地面、墙面、吊顶、柜体、茶几、地毯、窗户、窗帘和软装。
- 自然光方向、室内辅助光、明暗层次和色温。
- 相机方位、高度、焦段感、透视、构图和摄影质感。

不要沿用图1原沙发的款式、颜色、结构、摆向或体量。

详细规则见 `references/analysis-rules.md`。

### 2. 解析图2产品

优先识别：

- 原始拍摄角度：正面、左前、右前或强斜向。
- 近端、远端、主体轴线、透视收缩和空间延伸方向。
- 模块数量、组合关系、左右方向、转角、贵妃位、平台、扶手、靠背、靠包、抱枕和座面接缝。
- 坐深、坐高、底座厚度、前沿角度、颜色、材质和纹理。
- 所有模块的共同落地基准面。

看不清的细节标记为不确定，不自行补造。

### 3. 用产品视角重构空间

始终遵循“空间适配沙发，而不是沙发适配空间”：

- 保持图2原始近大远小关系，不强行转正或镜像。
- 根据沙发角度重新安排相机、地毯、茶几、地砖缝、窗户、餐厨和柜体方位。
- 只允许调整场景左右关系和家具位置，不改变产品结构。
- 保持主通道连续畅通。后方为主要通道时，提示词明确保留约90—110cm通行宽度；尺度不适用时改写为“宽敞连续的主通道”，不要硬套数值。
- 所有模块共享同一水平地面，补充连续接触阴影，防止翘起、悬空、错层和倾斜。
- 人物只在用户要求或图1人物对氛围明显有价值时加入；不得遮挡主要模块、接缝、转角和靠包。

### 4. 生成最终提示词

按照 `references/prompt-template.md` 组织内容，优先保留：

1. 产品唯一依据与不可变结构。
2. 原始视角、近端远端和空间透视。
3. 同一水平面、稳定贴地和连续接触阴影。
4. 场景风格、布局、主通道和客餐厨关系。
5. 茶几、地毯、窗户、灯光、机位和摄影质感。
6. 人物要求，仅在适用时加入。

提示词目标为1800—2500个中文字符，硬上限为3000个可见字符。内容超限时先删除重复形容词、次要摆件和非关键参数，不得删除产品锁定、透视、贴地或主通道约束。

### 5. 校验

使用 `references/quality-checklist.md` 完成自检。

代码执行可用时，将最终提示词正文通过标准输入传给：

```bash
python scripts/validate_prompt.py
```

脚本失败时必须压缩或修正后再输出。无法运行脚本时，按同一规则人工校验。

## 固定输出格式

始终使用以下结构：

```markdown
## 简短分析

- **场景风格：** ……
- **空间布局：** ……
- **沙发视角：** ……
- **空间调整：** ……
- **风险提醒：** ……

## 即梦完整提示词

```text
……
```
```

简短分析控制在5点以内，直接说明关键判断，不复述整段提示词。

## 最终提示词硬性规则

- 不出现“参考图1”“图1”“图2”“示例图”“第一张图”“第二张图”“原场景图”等依赖当前对话图片顺序的表述。
- 可以使用“我会上传一张沙发白底产品图”或“以我上传的沙发白底产品图作为唯一产品依据”。
- 场景必须写成独立、完整、可执行的文字描述。
- 不生成或编辑图片；只输出分析和提示词。
- 不使用固定沙发颜色作为通用前提。颜色和材质默认写为“保持产品图原有颜色和材质”；只有用户明确要求写死时才具体命名。
- 不虚构无法从图片判断的精确尺寸、品牌、建筑地点或相机型号。
- 禁止镜像、强行转正、改款、增减模块、合并模块、改变左右关系、颜色或材质。
- 结果必须让人一眼认出是白底产品图中的同一款沙发。
